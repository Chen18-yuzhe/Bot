# RAG（检索增强生成）学习笔记

RAG 的目标是让模型回答时优先依据可更新、可追溯的外部资料，而不是只依赖模型参数中的旧知识。它尤其适合私有文档、产品手册和频繁变化的信息。

## 工作流：检索 → 增强 → 生成

1. **检索（Retrieve）**：把用户问题转成查询，在知识库中找出最相关的文档片段。本项目现有实现按文件分块、中文 n-gram 与英文词项做轻量排序，并限制返回数量。
2. **增强（Augment）**：将命中的片段以清晰边界放入系统上下文，同时要求模型只在相关时引用，并在资料不足时说明不确定性。
3. **生成（Generate）**：携带“原问题 + 对话历史 + RAG 上下文”调用 LLM；模型仍可按需要调用实时工具，不能把本地资料误作实时事实。

## 本次实现

`RagRetrievalSkill` 在每条非空消息进入 LLM 前执行。它从当前会话所属账户的私有知识库检索，未命中时不注入“无结果”文本，避免无效 token 和模型误解。`SkillManager` 将所有自动发现的 Skill 按顺序组成管线，因此新增能力不需要修改消息路由。

## 质量与安全要点

- **分块**：块过大降低命中精度，块过小则缺乏语义。当前约 900–1200 字符，后续可按标题和段落切分。
- **排序**：当前为词项匹配；资料增加后可升级为向量召回、关键词召回的混合检索，再用 reranker 精排。
- **上下文预算**：限制 Top-K 和单片段长度，防止挤占模型输出空间。
- **抗幻觉**：上下文标注为资料片段，并要求资料不足时透明说明；检索不到不等于事实不存在。
- **隔离**：按会话解析账户并在对应目录检索，避免将一个用户的资料注入另一个用户的对话。

## 可演进方向

引入 embedding 索引和元数据过滤（时间、文档类型、权限），为回答附带来源文件与片段编号，并记录命中率、上下文长度和用户反馈来评估检索质量。
